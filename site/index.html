How do I know it works?

See it with your own eyes.

1Make some noise

Paste this into Claude Code and send it:

Run this: for i in $(seq 900); do echo "Compiling module $i of 900"; done; echo "error: it worked"

Claude will get a short [chroni: trimmed…] note instead of the wall of text and still spot the error. Without Chroni, it reads all 900 lines.

2Check the counter

Type /chroni any time to see how many tokens it has saved, this session and all time.

> /chroni
chroni is on. Saved ~7.8k tokens this session,
~41.2k tokens all time across 12 trimmed outputs.

Want the raw output for one command? Put CHRONI=off in front. Want it off entirely? /chroni off.

Questions

Fair questions.

Does it make Claude dumber?

No. It only removes repeated lines, progress bars and the boring middle of long logs. Every error and warning stays, and the full output is one file read away. When Claude reads files, diffs or search results on purpose, Chroni doesn't touch them.

How much will I actually save?

It depends on how noisy your work is. On commands like builds, installs, test runs and big listings, it's usually 30–98% of that output. Small commands aren't changed at all. Type /chroni to see your real number.

Does it send my code anywhere?

No. Everything runs on your machine, inside Claude Code. Full logs are saved in ~/.claude/chroni/logs and rotate, so they don't pile up.

What about really huge outputs?

Past about 30KB, Claude Code steps in before any plugin can: it saves the output to a file and shows Claude a short preview. For failing commands it cuts out the middle. When that happens, Chroni's note tells Claude what was cut and how to get it back, so it never thinks it saw everything when it didn't.

What's /handoff?

When a session gets long, every message re-sends the whole history. /handoff has Claude write a short summary file; then you /clear and continue from it with a fraction of the context.
